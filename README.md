# Powdar

A simple ski-snow map for every US state with ski resorts (359 resorts in 35 states): one fixed map per state
with each resort's new snow, 3- and 7-day forecast, snowpack vs normal (or NOAA snow depth), and in Colorado
opening and closing days. Pick a state from the list header; the address remembers it (…/powdar/#ut).
Tap any resort for its forecast, weather, live lifts, season chart and sources.

**On Android:** open the site in Chrome, tap ⋮ → *Install app* (or *Add to Home screen*).

## Where the data comes from

| What | Source | Covers |
|---|---|---|
| Open/closed, lifts, runs, 24/48 hr snow, base | [Colorado Ski Country USA feed](https://snow.coloradoski.com/view/publicreport-feed) | 20 member resorts |
| Snow forecast (7 days) | Blend of the [National Weather Service](https://www.weather.gov/documentation/services-web-api) and four models via [Open-Meteo](https://open-meteo.com) (ECMWF, GFS/HRRR, GEM, ICON) at mid-mountain elevation | All 26 resorts |
| Season snowpack vs normal | [NRCS SNOTEL](https://www.nrcs.usda.gov/wps/portal/wcc/home/) station nearest each resort, 1991–2020 median | All 26 resorts |
| Daily weather (sky, wind, chance of precipitation) | [National Weather Service](https://www.weather.gov/documentation/services-web-api) text forecast | All 26 resorts |
| Live lift-by-lift status | Each resort's own lift data: MtnPowder (A-Basin, Steamboat, Winter Park), Powdr (Copper, Eldora), Aspen Snowmass feed (4 mountains), and the Loveland, Monarch and Telluride lift pages. Endpoints as tracked by [Liftie](https://github.com/pirxpilot/liftie) (BSD-3). | 12 resorts |
| Snow on the ground at each resort | [NOAA NOHRSC](https://www.nohrsc.noaa.gov/nsa/) SNODAS snow model (daily) | All 26 resorts |
| Typical season snowfall | [ZRankings](https://www.zrankings.com/articles/best-snow-in-colorado) "True Snow" (patrol and avalanche-center records) | 19 resorts |
| Snow on the ground (map layer) | [NOAA NOHRSC snow analysis](https://www.nohrsc.noaa.gov/nsa/) | Everywhere, daily |
| Planned opening dates | Hand-entered in `src/resorts.js` (`PLANNED`) | Vail, Beaver Creek, Breckenridge, Keystone, Crested Butte, Wolf Creek |

Vail Resorts' sites block automated requests, so those mountains show planned dates instead of a live status.

### How the forecast works

Each model's hourly precipitation and temperature, adjusted to the resort's mid-mountain elevation, becomes snow using a
temperature-based snow-to-liquid ratio (wet near freezing, fluffier in the cold). The app shows the middle of the five
forecasts as the headline and the 2nd-lowest to 2nd-highest as the likely range. If the models are unreachable it
falls back to the Weather Service alone. Days 8–14 come from the models that reach that far (ECMWF, GFS), and
the season chart's dashed line adds the models' forecast snow water to today's snowpack.

## Resorts outside Colorado

`src/us-resorts.json` is generated by `scripts/us-resorts.mjs` from [OpenSkiMap](https://openskimap.org)'s ski
areas (© OpenStreetMap contributors, ODbL): operating downhill areas with 2+ lifts and 500 ft of vertical (or
1 lift and 1,000 ft, or 3+ lifts and 200 ft for Midwest-style hills). It also looks up each resort's NWS grid,
nearest SNOTEL station with a 30-year record, and any JSON lift feed known to [Liftie](https://github.com/pirxpilot/liftie).
Re-run yearly:

```sh
curl -o ski_areas.geojson https://tiles.openskimap.org/geojson/ski_areas.geojson
node scripts/us-resorts.mjs ski_areas.geojson liftie-feeds.json
```

Colorado stays hand-curated in `src/resorts.js` (Colorado Ski Country feed, opening dates, chosen stations).

## How it runs

A GitHub Action (`.github/workflows/update.yml`) runs every 15 minutes during lift hours and hourly overnight
(triggered by GitHub's scheduler and by a small launchd job on the maintainer's Mac,
`~/Library/LaunchAgents/com.powdar.trigger.plist`, since GitHub's scheduler can lag): it runs the tests, fetches fresh data into
`public/data.json` and publishes `public/` to GitHub Pages. Colorado refreshes fully every run; other states refresh forecasts,
snowpack and NOAA snow depth about every 4 hours (a few states per run, to stay inside Open-Meteo's free
allowance) and live lifts every run. Each state is written to `public/data/<state>.json`, with `public/states.json`
indexing them for the picker. There is no server.

## Past seasons

`public/history/` holds each snow station's past winters (2005–06 onward), used for the season picker and the
color bands (driest 10% → snowiest 10% of years) on each resort's season chart. Impossible sensor
readings (snow water jumping more than ~4″ up or ~3″ down in a day and then returning) are dropped. Past seasons never change, so
regenerate once a year after the season ends: `npm run history`.

## Each fall

Update `PLANNED` in `src/resorts.js` with the new season's dates for the resorts without a live feed, and run
`npm run history` to add the season that just ended.
Seasons without an entry show "Opening date TBA" instead of stale dates.

## Local development

```sh
npm run build    # fetch live data into public/data.json
npm run preview  # http://localhost:8787 (file URLs keep a literal __V__ locally; CI stamps it)
npm test
```

No npm dependencies; needs Node 20+. Leaflet 1.9.4 (BSD-2) is vendored in `public/vendor/leaflet/`.
Map tiles come from OpenTopoMap (no key needed).
